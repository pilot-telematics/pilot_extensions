# Первое расширение PILOT: от Hello World до запуска

Это руководство предназначено для человека, который знает PILOT как пользователь, но ещё не создавал расширения и не настраивал хостинг.

Цель — создать простое расширение «Привет, PILOT!», разместить его в интернете, зарегистрировать в панели Администратора и открыть в PILOT.

Проходите шаги по порядку. Сначала добейтесь запуска простого экрана. Затем добавляйте новые функции по одной.

## Что понадобится

- доступ к PILOT;
- доступ к панели Администратора PILOT;
- браузер;
- адрес электронной почты для регистрации на хостинге;
- AI-помощник, который может читать этот репозиторий или его документы.

Не передавайте AI пароль, код из письма, код двухфакторной авторизации или ключ восстановления. Введите эти данные сами, только на официальном сайте хостинга.

## Шаг 1. Попросите AI создать Hello World

Скопируйте этот запрос в AI. AI должен помочь выбрать уникальное техническое имя расширения и дождаться вашей проверки в панели Администратора.

```text
Я впервые создаю PILOT Extension и не умею программировать. Помоги мне создать и запустить «Привет, PILOT!» по одному шагу. После каждого шага скажи, что я должен увидеть, и дождись моего ответа.

Работай по https://github.com/pilot-telematics/pilot_extensions. Сначала прочитай AI_SPECS.md, examples/hello_world/Module.js, DEPLOY.md и docs/REGISTER_EXTENSION_RU.md. Соблюдай эти документы. Не проси меня прислать файлы, пока не проверишь ссылки. Если файл недоступен, скажи об этом и не утверждай, что прочитал его.

Сначала предложи уникальный lowercase snake_case slug и попроси проверить его в отдельной панели Администратора PILOT → Расширения. Дождись подтверждения до создания файлов.

Затем создай минимальное расширение: вкладка слева и панель с текстом «Привет, PILOT!». Помоги опубликовать его, зарегистрировать в панели Администратора, выдать доступ аккаунту, включить в PILOT и проверить результат.
Действуй строго по одному действию за сообщение. После действия остановись и дождись моего ответа. Если я пишу «Нашёл» или «Готово», но следующий шаг зависит от конкретного экрана или результата, попроси назвать видимый пункт или результат. Не делай вывод, что публикация, доступ или запуск прошли успешно, пока я не подтвержу соответствующую проверку.
```

AI должен соблюдать контракт PILOT. Расширение — это модуль внутри PILOT, а не отдельный сайт. Для этого первого шага не нужны карта, API, настройки и backend.

## Шаг 2. Выберите бесплатный статический хостинг

Для Hello World нужны только статические файлы. Выберите один вариант:

| Вариант | Выберите его, если… | Как публиковать |
|---|---|---|
| Cloudflare Workers: Upload your static files | Вы хотите загрузить готовые статические файлы или ZIP через браузер без Git. | Откройте Workers & Pages, выберите **Upload your static files**. Адрес проекта будет использовать `workers.dev`. |
| GitHub Pages | Вы готовы хранить исходники в GitHub и хотите публиковать новые версии из репозитория. | Создайте публичный репозиторий, загрузите файлы через сайт GitHub и включите Pages для ветки `main`. |

Для простого Hello World не нужны домен, сервер или командная строка. Хостинг выдаст URL на своём домене.

Код расширения публичен. Это ожидаемо для клиентского кода PILOT. Не помещайте в файлы пароли, приватные ключи или секретные API-токены.

### Вариант A. Cloudflare Workers: загрузка статических файлов без Git

1. Откройте [страницу регистрации Cloudflare](https://dash.cloudflare.com/sign-up). Официальная [инструкция по созданию аккаунта](https://developers.cloudflare.com/fundamentals/account/create-account/) описывает регистрацию и подтверждение адреса электронной почты.
2. Создайте аккаунт и подтвердите адрес электронной почты. Пароль и коды подтверждения вводите сами.
3. В панели Cloudflare откройте **Workers & Pages** и нажмите **Create application**.
4. На экране **Make something new** выберите **Upload your static files**. Не выбирайте подключение GitHub или GitLab, Hello World, шаблон или ссылку **Continue to Pages**. В текущем интерфейсе Pages помечено как legacy workflow.

5. Введите имя проекта, например `pilot-hello-world`.
6. Загрузите ZIP или папку с файлами. Убедитесь, что в корне архива находятся `Module.js` и `index.html`, а не дополнительная папка с этими файлами. Если экран загрузки отличается, сообщите AI точные названия видимых кнопок или пришлите скриншот.
7. Завершите публикацию по подсказкам Cloudflare.
8. Откройте выданный Workers адрес. Он имеет вид `https://pilot-hello-world.<поддомен>.workers.dev/`.

Если открылась форма подключения Git, вернитесь к экрану **Make something new** и выберите **Upload your static files**. Не загружайте ZIP в форму подключения репозитория.

### Вариант B. GitHub Pages

[GitHub Pages доступен в бесплатном тарифе для публичных репозиториев](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages). Сам сайт будет общедоступным.

1. Откройте [страницу регистрации GitHub](https://github.com/signup). Официальная [инструкция GitHub](https://docs.github.com/en/account-and-profile/how-tos/account-management/creating-an-account-on-github) описывает создание аккаунта и подтверждение электронной почты.
2. Создайте аккаунт и подтвердите адрес электронной почты. Пароль и коды подтверждения вводите сами.
3. Создайте новый **публичный** репозиторий, например `pilot-hello-world`.
4. Откройте репозиторий и выберите **Add file → Upload files**.
5. Загрузите файлы расширения. `Module.js` должен находиться в корне репозитория рядом с `index.html`.
6. Нажмите **Commit changes**.
7. Откройте **Settings → Pages**.
8. В разделе публикации выберите **Deploy from a branch**, ветку `main` и папку `/ (root)`. Сохраните настройки.
9. Дождитесь завершения публикации. Официальные шаги описаны в [руководстве GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).
10. Откройте сайт по адресу `https://<имя-пользователя>.github.io/pilot-hello-world/`.

### Как AI помогает с регистрацией

AI может описать текущий экран и подсказать, куда нажать. Если он не управляет браузером, отправьте ему скриншот экрана без паролей и кодов подтверждения.

После каждого действия проверяйте результат. Если сайт показывает другие названия пунктов, попросите AI сопоставить их с текущим экраном. Не сообщайте AI пароль, код из письма, CAPTCHA или код двухфакторной авторизации.

Если AI попросил подтвердить, что кнопка или вариант загрузки появился, ответьте точным текстом этого пункта. Если экран не совпадает с инструкцией, остановитесь и сообщите заголовок экрана и видимые кнопки. AI не должен продолжать с предполагаемого экрана.

## Шаг 3. Проверьте размещённые файлы

Откройте полный публичный URL `Module.js` в браузере:

```text
https://<хост>/<путь>/Module.js
```

Браузер должен показать JavaScript. Страница не должна показывать ошибку 404 или главную HTML-страницу.

Если файлы загружены в корень сайта, URL будет таким:

```text
https://<хост>/Module.js
```

Если они лежат во вложенной папке, сохраните эту папку в URL. Например, если файл находится в `/pilot_hello_a31f/Module.js`, базовый URL будет `https://<хост>/pilot_hello_a31f/`. Используйте свой подтверждённый slug.

**Для панели Администратора нужен базовый URL папки. Не добавляйте к нему `Module.js`.** Записывайте URL со слэшем `/` в конце. В текущей реализации PILOT генератор конфигурации сам добавляет этот слэш, если его нет.

## Шаг 4. Зарегистрируйте расширение

Следуйте [руководству по регистрации расширения](REGISTER_EXTENSION_RU.md). Для первого расширения укажите:

- **Название:** подтверждённый уникальный slug, например `pilot_hello_a31f`;
- **Полное название:** `Привет, PILOT!`;
- **Описание:** `Демонстрационное расширение с приветствием в PILOT.`;
- **URL-адрес:** базовый URL папки, например `https://<хост>/`;
- **Опубликовано:** включено;
- **Класс значков:** по умолчанию выбрана звезда. Оставьте её или выберите другой значок из списка.
- **Автор:** ваше имя.

В панели Администратора откройте **Расширения**, добавьте запись и сохраните её кнопкой **Обновить**. Список называется «Расширения», а не «Приложения».

## Шаг 5. Выдайте доступ и включите расширение

Для первого запуска оставьте включённым **Доступно всем аккаунтам** или выберите аккаунт, под которым вы войдёте в PILOT. Сохраните доступ.

Затем:

1. Войдите в PILOT под этим аккаунтом.
2. Откройте меню пользователя.
3. Выберите **Расширения**.
4. Найдите «Привет, PILOT!» и включите переключатель.
5. Откройте расширение.

Вы должны увидеть панель с текстом «Привет, PILOT!». Если не видите её, проверьте адрес и имя по разделу ниже.

## Шаг 6. Проверьте изменения

После изменения файлов:

- **GitHub Pages:** загрузите новые файлы в репозиторий и подтвердите изменения. GitHub опубликует новую версию.
- **Cloudflare Workers:** откройте тот же проект и выберите **New deployment**. Загрузите новую версию в существующий проект. Не создавайте второй проект.

Сохраните прежний базовый URL и техническое имя расширения. Откройте `Module.js` по публичному URL и найдите маркер версии или уникальную строку из изменения. Затем перезагрузите PILOT и проверьте функцию. Не просите пользователя искать поле версии, если его нет в файле.

При добавлении пункта в меню заранее сообщите AI точное место: раздел PILOT, имя дерева, тип выбранного элемента и способ открытия меню. Например: «Main → Online; объект; правая кнопка мыши». Это помогает не перепутать меню объекта с меню группы или другой панели.

## Если первый запуск не получился

| Что вы видите | Что проверить |
|---|---|
| `Module.js` открывает 404 | Проверьте, что файл загружен в папку, соответствующую URL. Откройте полный URL ещё раз. |
| `Module.js` открывается, но PILOT не загружает расширение | В поле URL укажите базовый URL папки, а не URL `Module.js`. После добавления расширения или изменения URL подождите до 10 минут: Nginx обновляет конфигурацию по расписанию раз в 10 минут. |
| PILOT сообщает, что класс не найден | Проверьте в инструментах разработчика браузера, загрузился ли `/store/<ваш_slug>/Module.js`. Slug в панели Администратора и имя класса должны совпадать: `Store.<ваш_slug>.Module`. После обновления конфигурации выполните полную перезагрузку страницы. |
| Расширение не отображается в списке | Проверьте **Опубликовано** и доступ текущего аккаунта. |
| Вкладка есть, но основная панель пустая | Попросите AI проверить связь `navTab.map_frame = mainPanel`, добавление вкладки в `skeleton.navigation` и панели в `skeleton.mapframe`. |

## После успешного Hello World

Добавляйте по одной функции за раз:

1. Измените текст, заголовок или стиль.
2. Добавьте небольшое действие, например кнопку.
3. Покажите данные из документированного API PILOT. Сначала прочитайте [справочник совместимости API](PILOT_API_COMPATIBILITY_RU.md).
4. Добавьте маркер на текущую карту. Сначала прочитайте [справочник MapContainer](MapContainer_RU.md).
5. Добавьте глобальные настройки или настройки аккаунта через [API настроек расширения](PILOT_RUNTIME_UTILS_RU.md#api-настроек-расширения). Эти значения доступны в браузере.
6. Добавьте backend только тогда, когда нужна серверная логика или секреты. См. [руководство разработчика](HUMAN_EXTENSION_GUIDE_RU.md) и [руководство по размещению](../DEPLOY.md).

Для идеи со многими функциями используйте [шаблон бизнес-идеи](ChatGPT_Prompts/Business_Idea_RU.md) после того, как прошли первый запуск.
